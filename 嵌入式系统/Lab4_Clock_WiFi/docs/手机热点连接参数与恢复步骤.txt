实验四：手机热点双向透传测试记录
日期：2026-10-22

已验证结果
电脑与 ESP 模块均连接 iPhone 热点。
串口发送 hello，电脑 TCP Server 收到 hello。
电脑 TCP Server 发送 1234，串口收到 1234。
这只验证了通信链路；按钮同步时间等后续功能尚未在当前聊天中验证。

本次连接参数
热点名称：Miles
热点密码：在手机个人热点设置中查看，不在此文档重复记录。
iPhone 个人热点：允许其他人加入；保持最大兼容性开启。
串口：COM3，115200，8 数据位，无校验，1 停止位。
电脑 WLAN IPv4：172.20.10.8（重新连接热点后须重新确认）。
模块本次 IPv4：172.20.10.9（由接收记录得知，重新连接后可能改变）。
电脑协议：TCP Server。
电脑监听端口：8899。
模块：TCP 客户端，单连接，透传。

下次手动恢复连接
1. 打开手机热点；电脑与模块连接同一个热点。
2. 电脑运行 ipconfig，查看无线局域网适配器 WLAN 的 IPv4。
3. USR 右侧选择 TCP Server、本次电脑 WLAN IPv4、端口 8899，再开始监听。
4. 若模块还在透传：停止发送至少 1 秒；一次发送 +++，不附加回车换行；再等至少 1 秒；发送 AT，确认 OK。
5. 在命令模式中先查询 AT+CWJAP?。若尚未连接正确热点，再用 AT+CWJAP="热点名称","热点密码" 连接，等 WIFI GOT IP 和 OK。
6. 逐条发送下列命令，每条成功后再发下一条；将占位内容替换为电脑的实际 IPv4：
AT+CIPMODE=0
AT+CIPMUX=0
AT+CIPSTART="TCP","电脑当前IPv4",8899
AT+CIPMODE=1
AT+CIPSEND
若已有旧 TCP 连接，先用 AT+CIPCLOSE 关闭后再建立新连接。
7. 出现 > 后，左侧发送 hello，右侧发送 1234，检查双向接收。
普通 AT 命令沿用已成功的回车换行发送方式；+++ 是例外，不加回车换行。

关于保存
本文件和截图是测试记录，未向 ESP 模块写入任何配置。
接收框 Save… 用于导出接收记录，不会保存 TCP 会话。
断电后需要重新建立 TCP 连接；本次成功不证明自动重连已配置。
AT+CIPMODE 设置不会作为透传启动配置永久保存。
ESP-AT 支持使用 AT+SAVETRANSLINK 保存上电透传参数，但它会记住目标地址；电脑 IP 改变时必须更新。
Wi-Fi 配置保存命令随固件版本而异，先通过 AT+GMR 确认版本。
若后续由单片机发送 AT 命令初始化，应由程序负责连接，避免与上电直接进入透传的设置冲突。
